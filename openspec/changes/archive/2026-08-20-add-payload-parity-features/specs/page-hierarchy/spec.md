## Purpose

This capability gives editors predictable page slugs and parent-child organization while visitors receive stable nested URLs and navigable ancestry.

## ADDED Requirements

### Requirement: Optional page parent
Every page SHALL accept either one parent page or no parent page. A page without a parent SHALL be a root page.

#### Scenario: Create a root page
- **WHEN** an editor creates a page without selecting a parent
- **THEN** the page SHALL be created as a root page

#### Scenario: Create a child page
- **WHEN** an editor creates a page and selects another page as its parent
- **THEN** the page SHALL be created as a child of the selected parent

### Requirement: Hierarchical public URLs
A page's public URL SHALL consist of each ancestor's slug in root-to-parent order followed by the page's own slug. A root page SHALL be reachable at `/<slug>`, and the designated home page SHALL remain reachable at `/`.

#### Scenario: Visit a root page
- **WHEN** a visitor requests a root page whose slug is `about`
- **THEN** the page SHALL resolve at `/about`

#### Scenario: Visit a nested page
- **WHEN** a visitor requests a page with slug `team` whose parent has slug `about`
- **THEN** the page SHALL resolve at `/about/team`

#### Scenario: Visit the home page
- **WHEN** a visitor requests `/`
- **THEN** the designated home page SHALL resolve

### Requirement: Ancestor breadcrumbs
A public page with ancestors SHALL display breadcrumbs for every ancestor in root-to-parent order, and each breadcrumb SHALL link to that ancestor's public URL.

#### Scenario: View breadcrumbs on a nested page
- **WHEN** a visitor views a page with one or more ancestors
- **THEN** the page SHALL display a linked breadcrumb for each ancestor in root-to-parent order

### Requirement: Acyclic page hierarchy
The system MUST prevent a page from becoming its own ancestor, whether directly or through descendants. An invalid parent change SHALL be rejected with an error explaining that it would create a cycle.

#### Scenario: Select the same page as parent
- **WHEN** an editor attempts to set a page as its own parent
- **THEN** the change SHALL be rejected with an error explaining that a page cannot be its own ancestor

#### Scenario: Select a descendant as parent
- **WHEN** an editor attempts to set one of a page's descendants as that page's parent
- **THEN** the change SHALL be rejected with an error explaining that the change would create a cycle

### Requirement: Parent changes update public URLs
Changing a page's parent SHALL immediately change the page's public URL to reflect its new ancestor chain. The page's former URL SHALL no longer resolve to that page.

#### Scenario: Move a page to another parent
- **WHEN** an editor changes a page's parent and the change is accepted
- **THEN** the page SHALL resolve at the URL formed from its new ancestor chain and own slug
- **AND** its former URL SHALL no longer resolve to that page

### Requirement: Parent deletion protection
A page with one or more children MUST NOT be deleted. The deletion attempt SHALL be rejected with an error stating that existing child pages are the obstacle and must first be reassigned or deleted.

#### Scenario: Delete a page with children
- **WHEN** an editor attempts to delete a page that has one or more children
- **THEN** the deletion SHALL be rejected with an error stating that child pages must first be reassigned or deleted

#### Scenario: Delete a page without children
- **WHEN** an editor deletes a page that has no children
- **THEN** the deletion SHALL be accepted

### Requirement: Editable title-derived slugs
When an editor starts a new page with a non-empty title, its slug SHALL be generated by lowercasing the title and replacing spaces with hyphens. The editor SHALL be able to edit the generated slug before or after creation.

#### Scenario: Generate a slug from a title
- **WHEN** an editor enters the title `Our Team` for a new page
- **THEN** the generated slug SHALL be `our-team`

#### Scenario: Edit a generated slug
- **WHEN** an editor changes a generated slug to another valid slug
- **THEN** the edited slug SHALL be retained

### Requirement: Sibling slug uniqueness
A generated or editor-supplied slug MUST be unique among pages with the same parent, including among root pages that have no parent. A conflicting slug SHALL be reported as an error and the page SHALL NOT be saved until the editor supplies a unique sibling slug.

#### Scenario: Reject a sibling slug collision
- **WHEN** an editor attempts to save a page with the same slug as another page under the same parent
- **THEN** the save SHALL be rejected with an error identifying the sibling slug collision

#### Scenario: Allow the same slug under different parents
- **WHEN** an editor saves pages with the same slug under different parents
- **THEN** the pages SHALL be saved with distinct public URLs formed from their respective ancestor chains

### Requirement: Slug for an empty title
A new page with an empty title SHALL remain creatable. The system SHALL provide a non-empty, collision-free fallback slug that the editor can edit.

#### Scenario: Create a page with an empty title
- **WHEN** an editor creates a page while its title is empty
- **THEN** the page SHALL receive a non-empty slug that does not collide with any sibling slug
- **AND** the editor SHALL be able to edit that slug
